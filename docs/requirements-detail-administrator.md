# 機能要件詳細定義書（2. 管理者・運営者向け機能）

## 1. 認証・ダッシュボード・権限管理
### 1.1 管理者ログイン・認証（A-01）

* **概要**：管理者（`ADMIN`）および運営者（`OPERATOR`）専用の管理画面Webログイン認証。

* **処理詳細**：
* メールアドレスまたはログインID、およびパスワードを用いた認証。

* 認証後、`users.role` が `ADMIN` または `OPERATOR`（または `is_admin = true`）のアカウントのみ管理コンソールへのアクセスを許可。一般ユーザー・代表者はアクセス拒否。

* **2要素認証（2FA）**：管理画面ログイン時のワンタイムパスワードをLINEで発信。LINEから受け取ったワンタイムパスワードを次画面で入力して、ログイン完了。
* **セッション保持・排他制御**：同一アカウントによる複数ブラウザでの同時ログインは許可しない

---

### 1.2 管理者ダッシュボード（A-02）

* **概要**：運営上必要な主要KPI、集客状況、損益状況、要対応アラートを一画面で一元監視。

* **処理詳細**：
* **集客・定員充足状況**：直近大会の確定エントリー数／定員（`capacity`）のリアルタイム集計。

* **未対応有償キャンセル一覧**：`cancellations.admin_status = 'UNCONTACTED'`（未連絡）の案件を警告バッジ表示。

* **損益・売上概算**：大会ごとのエントリー料金（`entry_fee × 確定チーム数`）およびキャンセル請求額（`fee_amount`）の合算表示。

* **損益管理における「経費項目」**：コートレンタル代・ボール代・賞品代などの実費支出テーブルを設けて純利益を算出する。

---

### 1.3 アカウント管理・強制操作・権限設定

* **概要**：ユーザーアカウントの新規追加、強制削除、PW強制初期化、権限（`role`）の割り当て。

* **処理詳細**：
* **テスト・代理用アカウント追加**：管理画面から任意の属性（氏名、電話番号、初期GRANレベル、階級等）を指定して即時アカウント作成。

* **強制アカウント削除（停止）**：不正ユーザーや退会希望者を `status = 'SUSPENDED'` または物理削除。

* **パスワード強制リセット**：管理者がランダムな初期パスワードを再発行し、`is_initial_login = false` に戻してユーザーへ通知。

* **権限管理**：`users.role` を `ADMIN`（管理者）、`OPERATOR`（運営者）、`LEADER`（代表者）、`USER`（一般）の間で切り替え。

* **管理者と運営者の権限差分**：「運営者（`OPERATOR`）」ができる操作の範囲（ 運営者はスコア入力・エントリー確認のみ可能で、アカウント削除や大会料金変更・他管理者の権限変更は不可とする

* **アカウント削除時の外部キー制約動作**：チーム創設者や確定エントリーを持つユーザーを削除した場合の挙動（ON DELETE RESTRICT で削除拒否する。大会のキャンセルやチームの代表者権限移譲を行わないと削除できない仕様）

---

## 2. 大会管理
### 2.1 大会新規登録・一括登録・編集（A-07 / A-08）

* **概要**：大会の開催要項設定、定員・料金・アラート条件の登録および編集。

* **処理詳細**：
* **登録項目（必須）**：
  - 大会ID（`tournament_id`）：大会管理テーブルから自動採番
  - 大会名（`title`）
  - 開催日（`event_date`）
  - 種目区分（`category`: 男子団体/女子団体/ミックス団体/単/複）
  - GRANレベル（`max_gran_level` ,`min_gran_level`）
  - 会場名（`venue`）
  - 要項画像URL（`image_url`）
  - 定員数（`capacity`）
  - 参加費（`entry_fee`）

* **登録項目（必須ではない）**
  - 要項詳細説明（`description`）
  - 開始/終了時刻（`start_time`, `end_time`）
  - 受付期間（`entry_start_at`, `entry_end_at`）
  - 景品（`prize`）
  
* **一括登録**：複数日程・複数カテゴリの大会を一括で登録（バルクインサート対応）。

* **参加資格制限（レベル制限）カラム**
大会ごとに「GRANレベル上限・下限（例: Lv.550以下限定）」を設定する。

---

### 2.2 大会ステータス管理（A-03）

* **概要**：大会の公開・受付・進行ステータスの手動／自動切り替え。

* **処理詳細**：
  * ステータス値（`tournaments.status`）
    - `DRAFT`（未公開）
    - `UPCOMING`（受付前）
    - `OPEN`（受付中）
    - `CLOSED`（締切）
    - `FINISHED`（開催終了）
    - `CANCELLED`（中止）。

* 中止（`CANCELLED`）切り替え時は、確定エントリー保持者への中止通知案内およびキャンセル待ちの停止処理を実行。

* **大会中止時の有償キャンセル請求の扱い**：既に有償キャンセル料を請求中のユーザに関しては請求を取り下げる。

---

### 2.3 過去大会コピー作成（A-09）

* **概要**：過去に登録した大会設定を複製し、日付や一部項目を変更して素早く新規大会を作成。

* **処理詳細**：
* 複製元大会（`copy_from_id`）の `title`, `category`, `venue`, `description`, `capacity`, `entry_fee`, `alert_threshold` などを初期値としてロード。

* 開催日時や受付期間を修正して新規 `tournaments` レコードを発行。

---

### 2.4 ドロー表作成・JPEG出力機能

* **概要**：エントリー確定チーム／選手をもとに、当日のトーナメント表（ドロー表）を作成し、PDF形式で出力・保存。

* **処理詳細**：
* `entries(status = 'CONFIRMED')` のチーム／個人をシード順や抽選順（`tournament_matches.match_number`）に割り当て。

* **ドロー生成**
* システム上でドロー配置を決定後、.jpegを生成してストレージへ保存し、
`tournaments.draw_pdf_url` にURLをセット。
ドロー表の自動生成機能は実装しない。あくまで人の手で操作。

  * ドロー表作成手順
    - 管理者・運営者権限でログインした状態で大会詳細画面を開く
    - ドロー表作成ボタンをマウスオーバーし、「総当たり表」「トーナメント表」を選択。
    - UI上でドラッグ＆ドロップしてチーム・選手を手動配置
    - 完了後、画像化
    - 作成したドロー表は大会ごとのテーブルに保存。命名規則は「大会ID_drawtTable_2桁数字（01から）」

## 3. エントリー・参加者管理
### 3.1 エントリー一覧・検索・詳細確認（A-04 / A-10）

* **概要**：大会別のエントリー状況、チーム構成メンバーの確認・検索。

* **処理詳細**：
* エントリー一覧表示：申込日時、申込代表者、チーム名、構成メンバー（登録ユーザー・ゲスト・未定）
* 現在のエントリー状態でソート可能（`CONFIRMED`, `WAITING`, `CANCELLED`）。

* メンバー構成の内訳表示：`entry_members` の `member_type`（`REGISTERED` / `GUEST` / `PENDING`）を一覧展開。

---

### 3.2 エントリー代理登録（A-11）

* **概要**：LINE・口頭申込者やアプリ未登録者枠を、管理者が代理でエントリー登録。

* **処理詳細**：
* `entries.is_proxy = true` として起票。

* 申込者未登録の場合はゲスト扱い（`guest_name` 入力）。

* 枠が満員の場合は通常のユーザー同様に `waitlists` へ登録する。

---

### 3.3 キャンセル待ちキュー管理

* **概要**：キャンセル待ち（`waitlists`）の順番確認、手動繰り上げ、承諾ステータスの調整。

* **処理詳細**：
* 待機一覧（`queue_number` 順）および各レコードの状態（`WAITING` / `OFFERED` / `ACCEPTED` / `DECLINED` / `EXPIRED`）の確認。

* 手動による繰り上がり通知の即時再送や、期限の手動延長。

* **キュー順番の手動入れ替え**：管理者が特別な理由で `queue_number`（優先順位）を任意に入れ替え・繰り下げできる

---

## 4. キャンセル・精算管理
### 4.1 有償キャンセル対応管理

* **概要**：大会開催7日前〜当日に発生した有償キャンセル案件の請求・入金確認・免除対応を一括管理。

* **処理詳細**：
* 対象抽出：`cancellations.is_paid = true` のレコード一覧。

* 管理項目
- キャンセル申請日時、開催日残日数（`days_before`）
- キャンセル料率（50%/100%）
- 請求額（`fee_amount`）
- 対応ステータス（`admin_status`）
- 管理者メモ（`admin_notes`）。

* ステータス遷移：`UNCONTACTED`（未連絡） $\rightarrow$ `IN_CONSULTATION`（相談中） $\rightarrow$ `PAID_CONFIRMED`（入金確認済）または `WAIVED`（免除）。

---

## 5. 結果入力・ランキング・GRANレベル管理
### 5.1 大会結果・スコア入力・進行管理（A-13）

* **概要**：当日の試合進行管理、各対戦のスコア入力、大会最終順位（優勝・準優勝・2位トーナメント優勝等）の確定。

* **処理詳細**：
* **試合単位スコア入力**：`tournament_matches` の `score_detail`（例: 6-4, 3-6, [10-8]）および勝者（`winner_entry_id`）の記録。

* **最終順位登録**：チーム／個人ごとに `tournament_results.rank_type`（`T1_WINNER`, `T1_RUNNER_UP`, `L2_WINNER`, `PARTICIPATED` 等）を設定。

* **団体戦における「個人対戦スコア」の保持粒度**：団体戦（例: 男D・女D・混Dの計3本勝負）の場合、チーム勝敗（2-1）だけでなく各対戦ペア個人の勝敗・ゲーム数を保持する。

---

### 5.2 年間ランキング自動連動・手動調整（A-05）

* **概要**：大会結果確定に伴う年間ランキングポイントの自動加算と、ポイントの手動修正。

* **処理詳細**：
* 順位区分に応じて固定ポイント（参加: 3pt / 2位トーナメント準優勝・3位トーナメント優勝：5pt / 2位トーナメント優勝・1位トーナメント準優勝: 7pt / 1位トーナメント優勝: 10pt。）を `tournament_results.awarded_points` に記録し、`yearly_rankings.total_points` に即時合算。

* 管理者画面から特定のチームの年間累計ポイントを手動で加算・減算（ボーナスpt・ペナルティpt等）できる調整機能。

---

### 5.3 GRANレベル初期査定・変動反映

* **概要**：新規登録ユーザーの初期GRANレベル査定（100〜999）、および大会戦績に応じたイロレーティング自動更新・手動オーバーライド。

* **処理詳細**：
* **初期査定**：新規登録者一覧から未査定者（`is_level_calibrated = false`）を抽出し、管理者が主観・申告階級をもとに 100〜999 の数値を設定して `is_level_calibrated = true` に更新。

* **レート変動記録**：試合結果に基づき、変動前（`pre_gran_level`）、変動差分（`gran_level_diff`）、変動後（`post_gran_level`）を `tournament_results` に記録し、`users.gran_level` を更新。

* **団体戦・ダブルスにおけるGRANレベル計算式**：ペアの平均レートと相手ペアの平均レートから勝率期待値を算出する具体的な計算アルゴリズムの確定。





---

## 6. 連絡・広報

### 6.1 当日緊急連絡・一斉LINE配信（A-12）

* **概要**：天候不良による中止やコート変更などの緊急通知を、対象大会の確定エントリー者へ公式LINEから一斉配信。


* **処理詳細**：
* 対象大会を選択し、メッセージ本文を入力して送信。


* システムは対象大会の `entries(status = 'CONFIRMED')` に属する `users.line_user_id` を抽出し、LINE Messaging API（マルチキャスト/ブロードキャスト）で一括送信。


* 送信結果（成功/失敗件数、エラー詳細）を `notification_logs`（`delivery_type = 'URGENT_BROADCAST'`）へ保存。




* **不足・不明瞭な点（DB定義・仕様への確認事項）**：
* **配信対象の範囲選択**：「申込代表者のみ」に送るか、「チームに所属する全登録メンバー」に送るかを選択できる配信オプションの要否。
* **LINE未連携（メール登録）ユーザーへの通知**：`line_user_id` が存在しないユーザーに対する自動メール送信フォールバック機能の要否。





---

### 6.2 スケジュール閲覧・SNS広報用画像出力（A-06）

* **概要**：直近および今後の開催予定大会スケジュールを一覧表示し、Instagram/X（旧Twitter）等の広報用画像フォーマット（PNG/JPEG）としてダウンロード。


* **処理詳細**：
* 対象月・対象期間を指定し、開催日・種目・会場・定員・空き状況などをレイアウトした画像をクライアントサイド（HTML5 Canvas）またはサーバーサイド（Puppeteer/Sharp等）で動的レンダリングして出力。




* **不足・不明瞭な点（DB定義・仕様への確認事項）**：
* **画像出力テンプレートのカスタマイズ**：背景画像やカラーテーマ、掲載する大会の絞り込み条件（特定会場のみ等）の設定保存機能の要否。
